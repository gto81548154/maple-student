## 끝낼 때 확인한 것
- 설치와 빌드 성공을 확인했어요.
- 가짜 학원 서버를 붙인 크롬에서 실제로 눌러 봤어요: 더보기 → 장학금·친구 소개 열림(주소 #reward), 중1 학생이라 "중학생"이 미리 골라짐, 90점 → 빨간 안내·단추 꺼짐, 96점 → 날짜 안내 → 40일 전 날짜 → 기한 안내 → 10일 전 → 사진 안내 → 3000×4000 사진 올림(약 16KB로 줄어듦) → "1만원 기프티콘 대상" → 신청 → 목록에 "지급 완료 ✓"와 메모. 같은 학기·같은 시험 다시 → "이미 신청했어요". 고등학생 1·2등급 → 안 됨, 1·1등급 → 됨. 친구 소개: 이름·연락처 적기 전엔 단추 꺼짐, 보낸 뒤 목록에 "신청함", 같은 이름 다시 → "이미 신청했어요".
- 서버가 길을 모를 때(404): 목록은 "아직 불러올 수 없어요", 신청은 "지금은 신청할 수 없어요"만 뜨고 적은 내용은 남아 있었어요.

## 원장앱·워커 쪽에서 만들어야 하는 것(학생앱은 이 모양으로 보냄)
- 신청 보내기: `POST {워커}/student/reward-claim`, 몸통 `{ studentId, t, kind, … }`. 성적이면 `kind:"score", level("middle"|"high"), semester("2026-2"), exam("mid"|"final"|"both"), score(중학생 점수), midGrade·finalGrade(고등학생 등급), examDate, photoBase64, photoMime, amount:10000`. 친구 소개면 `kind:"referral", friendName, friendSchool, friendGrade, friendPhone, amount:30000`. 답 `{ success:true, id, at }`. 사진 한도 2MB(넘으면 413). 같은 신청이 이미 있으면 409로 답하면 학생앱이 "이미 신청했어요"로 보여줘요.
- 내 신청 목록: `GET {워커}/student/reward-claims?studentId=&t=`, 답 `{ success:true, items:[ { id, kind, at, status, reason, amount, …보낸 칸 그대로, photoKey } ] }`, 최신 먼저. status는 `pending`(신청함) / `checking`(확인 중) / `paid`(지급 완료) / `rejected`(지급 안 됨, reason에 이유).
- 성적표 사진 보기(원장앱용): 녹음 파일처럼 `/files/<photoKey>`.

## 정한 것
- 더보기에서 자리는 "안내" 묶음, 시험 정보 바로 아래로 했어요(학습 활동이 아니라 학원 안내 성격이라서).
- 과목은 영어 하나로 했어요(영어 학원이라 다른 과목은 없다고 봤어요). 안내 글에도 "영어"라고 적었어요.
- 친구 소개 기프티콘은 "친구가 학원에 등록하면" 주는 것으로 안내했어요. 등록 확인은 원장이 원장앱에서 하고 지급 완료로 바꾸면 돼요. 지급 시점(등록 즉시인지, 첫 달 수강료 뒤인지)은 답을 못 받아서 안내 글에는 안 적었어요.
- "한 달"은 시험 본 날로부터 30일로 했어요. 고등학생은 중간·기말 둘 다 봐야 하니 기말 시험 날짜를 기준으로 해요. 날짜는 학생이 직접 골라요(시험 일정 자료와 안 맞을 수 있어서 자동으로 채우지 않았어요).
- 고등학생 신청은 한 학기에 한 번(중간·기말 묶어서), 중학생은 중간·기말 각각 한 번씩 할 수 있게 했어요. 지급 안 됨으로 끝난 신청은 다시 보낼 수 있어요.
- 사진은 폰에서 긴 쪽 1600px·JPEG로 줄여서 보내요. 그래도 2MB를 넘으면 "사진이 너무 커요"라고 해요.
- 친구 소개는 이름(2자 이상)과 연락처(숫자 9자리 이상)가 있어야 보낼 수 있고, 학교·학년은 비워도 돼요.
- 선생님·원장이 학생 화면을 보기 전용으로 열었을 때는 신청이 막혀요(학생 이름으로 신청이 들어가지 않게).
- 중/고 판정은 시험 D-Day가 쓰는 같은 규칙(학교 이름·학년 글자)을 그대로 썼고, 그 함수를 밖에서 쓸 수 있게만 바꿨어요. 판정이 틀려도 학생이 알약으로 바꿀 수 있어요.
