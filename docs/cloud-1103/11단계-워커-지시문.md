# 11단계 — 워커(maple-sync) 녹음 제출 + 장학금·친구 소개 신청 받기

이 문서는 **maple-sync 워커 저장소**에서 쓰는 지시문이다. 워커 저장소에 `docs/cloud-1103/0-공통규칙.md`가 있으면 먼저 읽는다. 없으면 이 문서 맨 아래 "공통 규칙"을 따른다.

학생앱(maple-student)은 이미 완성돼 있다(145차수 녹음 제출, 146차수 장학금·친구 소개). 학생앱이 부르는 주소와 보내는 모양이 아래에 그대로 적혀 있으니 **그 모양에 맞춰** 워커 쪽을 만든다. 원장앱이 부를 길도 같이 만든다(원장앱은 12단계 지시문으로 따로 만든다).

## 미리 알아둘 것
- 학생 본인 확인: 학생앱은 모든 요청에 `t`(학생 링크의 토큰)를 붙인다. 기존 `/vocab-test-result`·`/mock/rounds`가 `studentId + t`를 확인하는 방식을 **그대로 재사용**한다(새로 만들지 않는다). 안 맞으면 401 또는 403.
- 원장 확인: 원장앱이 부르는 `/admin/...` 길은 기존 원장 열쇠(마스터 키) 확인 방식을 그대로 쓴다.
- 파일 저장: R2(마플보카 단어 데이터를 두는 버킷이 있으면 그 버킷, 없으면 새 버킷 `maple-files`). 표(메타) 저장: Turso. 기존 표 만드는 방식(마이그레이션)대로 표를 추가한다.
- 답 모양: 성공 `{ success:true, ... }`, 실패 `{ success:false, error:"<짧은 설명>", code:"<짧은 코드>" }`. CORS는 기존 학생앱·원장앱 길과 같게.
- base64 → 바이트로 풀 때 **2MB(2,097,152바이트)** 를 넘으면 413. 요청 본문 전체 크기 제한이 워커에 걸려 있으면 3MB 이상으로 열어 둔다(base64는 1.37배 커진다).

## A. 녹음 제출 (학생앱 145차수가 부른다)
원장앱 9단계 지시문으로 이미 만들었다면 **아래 모양과 같은지만 확인**하고 다른 점만 고친다.

표 `recordings`: `id`(문자열, 유일), `student_id`, `date`(YYYY-MM-DD, 학원 시간 기준), `label`(80자), `key`(R2 키), `dur`(초), `mime`, `at`(ISO), `heard`(0/1), `heard_at`, `memo`(200자), `created_at`.

1. `POST /student/recording` — body `{ studentId, t, label, dur, mime, dataBase64 }`
   - 검사: `label` 80자까지(비어도 됨), `dur` 1~90 정수, `mime`은 `audio/webm`·`audio/mp4`·`audio/ogg` 중 하나, 파일 2MB까지(넘으면 413).
   - R2 키: `rec/<studentId>/<YYYYMMDD-HHmmss>-<무작위 6자>.<webm|m4a|ogg>`. Content-Type은 받은 `mime`.
   - 답 `{ success:true, id, key, at }`.
2. `GET /student/recordings?studentId=&t=` — 최근 30일, 최신 먼저, 최대 100개.
   - 답 `{ success:true, items:[{ id, date, label, key, dur, mime, at, heard(true/false), memo }] }`.
3. `GET /files/<key>?sid=<studentId>&t=<토큰>` — R2 파일 내려주기.
   - 본인 확인: 키가 `rec/<sid>/` 또는 `reward/<sid>/`로 시작하고 `sid + t`가 맞을 때만. 또는 원장 열쇠(`?mk=` 기존 방식)면 모든 키.
   - **Range 요청을 꼭 지원한다**(`Range: bytes=...` → 206 + `Content-Range` + `Accept-Ranges: bytes`). 아이폰 사파리는 Range가 안 되면 소리를 재생하지 않는다. `Content-Type`은 저장 때 mime, `Cache-Control: private, max-age=3600`.
4. 원장용:
   - `GET /admin/recordings?date=YYYY-MM-DD` 또는 `?studentId=` 또는 `?unheard=1`(안 들은 것 전부) — 최신 먼저, 최대 200개. 답 items는 2번과 같고 `studentId`, `studentName`(학생 표에서 조인)을 더 붙인다.
   - `POST /admin/recording/heard` — body `{ id, heard(true/false), memo }`. `heard`가 true가 되면 `heard_at` 지금 시각. 답 `{ success:true }`.
   - `GET /admin/recordings/count?date=` — `{ success:true, unheard:<안 들은 개수>, today:<그 날짜 개수> }` (원장앱 홈 요약용).
5. 30일 자동 삭제: 기존 cron 핸들러에 하루 한 번 `at`이 30일 지난 행을 찾아 R2 파일 삭제 → 행 삭제. 한 번에 200개까지.

## B. 장학금·친구 소개 신청 (학생앱 146차수가 부른다)
표 `reward_claims`: `id`, `student_id`, `kind`(`score`|`referral`), `level`(`middle`|`high`), `semester`(예 `2026-2`), `exam`(`mid`|`final`|`both`), `score`, `mid_grade`, `final_grade`, `exam_date`, `photo_key`, `friend_name`, `friend_school`, `friend_grade`, `friend_phone`, `friend_student_id`(등록된 친구의 학생 id, 원장이 지급할 때 넣음), `amount`, `status`(`pending`|`checking`|`paid`|`rejected`), `reason`(200자), `at`, `updated_at`, `updated_by`.

1. `POST /student/reward-claim` — body `{ studentId, t, kind, ... }`
   - `kind:"score"`: `level, semester, exam, score(중학생), midGrade·finalGrade(고등학생), examDate, photoBase64, photoMime, amount`
     - 검사: `semester`는 `YYYY-1|2`, `exam`은 `mid|final|both`, 중학생은 `score` 0~100, 고등학생은 등급 1~9, `examDate`는 오늘 이전이고 **오늘로부터 30일 안**, 사진 필수(없으면 400 `code:"photo_required"`), 사진 2MB까지(넘으면 413), `photoMime`은 image/jpeg·image/png·image/webp.
     - 기준 확인은 워커에서도 한 번 더: 중학생 95점 이상, 고등학생 둘 다 1등급. 아니면 400 `code:"not_eligible"`.
     - 중복: 같은 학생·같은 `semester`·같은 `exam`에 `status`가 `rejected`가 아닌 행이 있으면 409 `code:"duplicate"`.
     - R2 키: `reward/<studentId>/<id>.jpg`(png·webp면 그 확장자). `amount`는 받은 값을 믿지 말고 **워커가 10000으로 고정**.
   - `kind:"referral"`: `friendName(2~30자), friendSchool, friendGrade, friendPhone(숫자만 세어 9자리 이상), amount`
     - 중복: 같은 학생이 같은 이름 또는 같은 번호(숫자만 비교)로 `rejected`가 아닌 행이 있으면 409. `amount`는 **30000으로 고정**.
   - 저장 시 `status:"pending"`. 답 `{ success:true, id, at }`.
2. `GET /student/reward-claims?studentId=&t=` — 최신 먼저, 최대 100개. 답 `{ success:true, items:[{ id, kind, at, status, reason, amount, level, semester, exam, score, midGrade, finalGrade, examDate, photoKey, friendName, friendSchool, friendGrade, friendPhone }] }` (사진 내용은 안 보낸다).
3. 원장용:
   - `GET /admin/reward-claims?status=pending|checking|paid|rejected|all` — 최신 먼저, 최대 300개. items는 2번과 같고 `studentId`, `studentName`, `studentSchool`, `studentGrade`를 더 붙인다.
   - `POST /admin/reward-claim/status` — body `{ id, status, reason, friendStudentId }`.
     - `rejected`면 `reason` 필수. `paid`면 `reason`은 메모(선택, 예 "11/5 카톡으로 보냄").
     - **친구 소개를 `paid`로 바꾸면서 `friendStudentId`를 주면**, 그 친구 학생 앞으로 행을 하나 더 만든다: `kind:"referral", friend_name:<소개한 학생 이름>, amount:30000, status:"paid", reason:"<소개한 학생 이름>이(가) 소개해서 받는 기프티콘"`. 이미 만들어져 있으면(같은 두 학생 짝) 또 만들지 않는다.
     - 답 `{ success:true }`.
   - `GET /admin/reward-claims/count` — `{ success:true, pending:<n>, checking:<n> }`.
4. 사진 보기: A-3의 `/files/<key>`를 그대로 쓴다(`reward/<sid>/`도 본인 또는 원장 열쇠).
5. 삭제 규칙 없음(지급 기록이라 남겨 둔다). 사진만 지급 완료·안 됨 뒤 **180일** 지나면 cron이 R2에서 지우고 `photo_key`를 비운다.

## C. 푸시 알림(기존 푸시 장치를 그대로 쓴다)
학생앱 푸시(공지 알림)를 보내는 기존 함수가 있으면 그걸 불러서 한 줄씩 보낸다. 없으면 이 절은 건너뛰고 검토 md에 적는다.
- A-4에서 `heard`가 처음 true가 되거나 `memo`가 새로 적히면 → "선생님이 녹음을 들었어요" (메모가 있으면 메모 앞 30자를 뒤에 붙임).
- B-3에서 `status`가 `paid`로 바뀌면 → "🎁 기프티콘 지급이 확인됐어요", `rejected`면 → "장학금 신청을 확인했어요. 앱에서 이유를 봐 주세요".
- 하루 같은 학생에게 같은 글을 두 번 보내지 않는다.

## 확인할 것(검토 md에 적는다)
- `wrangler dev`(또는 기존 로컬 실행법)로 띄워 curl로: 녹음 올리기(2초짜리 가짜 webm) → 목록 → `/files/` Range 요청이 206으로 오는지 → 들었음 표시 → 목록에 heard true.
- 장학금: 중학생 96점 + 사진 → 200, 같은 것 또 → 409, 90점 → 400 not_eligible, 사진 없음 → 400 photo_required, 2.5MB 사진 → 413, 40일 전 시험 날짜 → 400. 친구 소개 → 200, 같은 번호 → 409. 원장 paid + friendStudentId → 친구 쪽 행 하나 더.
- 토큰 틀리면 401/403, 원장 열쇠 없이 `/admin/` 부르면 401.
- 실제 배포(`wrangler deploy`)는 **원장이 한다**. 지시문에서 배포 명령은 실행하지 않는다.

## 공통 규칙(워커 저장소에 0-공통규칙.md가 없을 때)
- 기존 코드 스타일·폴더 구조·표 만드는 방식을 그대로 따른다. 지시한 것만 고친다. 줄끝은 LF 그대로.
- 끝낼 때 기존 테스트·빌드 명령이 있으면 통과시킨다.
- 깃: 작업이 끝나면 **main에 바로 커밋하고 올린다**(원장 결정 11-04).
- `docs/cloud-1103/워커-녹음·장학금-검토.md`를 만들어 같이 커밋한다. 쉬운 한국어로, 만든 길마다 "주소 / 받는 것 / 주는 것 / 확인법" 네 줄씩. 함수 이름·줄 번호는 적지 않는다.
- 막히거나 애매하면 멈추지 말고 가장 자연스러운 쪽으로 정한 뒤, 검토 md 맨 아래 "정한 것"에 한 줄씩 적는다.
