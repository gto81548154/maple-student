# 6단계 — 앱 고쳐 올려도 학생 폰에 옛 화면이 남는 것 (학생앱 142차수, 가지 `cloud-step6-1103`)

먼저 `docs/cloud-1103/0-공통규칙.md`를 읽는다.

## 원인(이미 조사한 것)
- `src/state/useAppUpdate.jsx`가 "새 판" 띠(🆕 새 버전이 있어요 [업데이트])를 띄우는데, **서비스워커(public/sw.js)가 바뀔 때만** 알아챈다. 그런데 sw.js는 푸시 알림용이라 배포 때 거의 안 바뀐다 → 띠가 안 뜬다.
- 실제로 옛 화면이 남는 이유는 브라우저/홈 화면 앱이 `index.html`을 캐시에 들고 있어서다(Vite가 만든 js는 이름이 매번 바뀌지만 index.html은 같은 이름).

## 고칠 것
1. **빌드 번호**를 넣는다. `vite.config.js`에 `define: { __BUILD_ID__: JSON.stringify(<빌드 시각 ISO 문자열>) }`. 빌드할 때마다 `public/version.json`도 같은 값으로 만든다(`{ "build": "..." }`) — vite 플러그인 하나로 `buildStart`에서 쓰면 된다(dev 때도 동작하게).
2. **새 판 확인**: `useAppUpdate`에 하나 더 — 앱이 켜질 때, 화면이 다시 보일 때(visibilitychange), 그리고 30분마다 `/version.json`을 `fetch(url + "?t=" + Date.now(), { cache: "no-store" })`로 읽어 `__BUILD_ID__`와 다르면 상태를 "found"로 만든다(기존 서비스워커 길은 그대로 둔다). 오프라인·실패는 조용히 무시.
3. **띠 글과 단추**: 지금 띠를 그대로 쓰되 글을 "🆕 업데이트가 있어요" + 단추 **[지금 적용]** 으로. 누르면 `applyAppUpdate` → 서비스워커 대기 중이면 지금 방식, 아니면(version.json 차이로 발견된 경우) 캐시를 비우고(`caches.keys()` 전부 delete) `location.reload()`. 시험·영상 중이면 지금처럼 안내만.
4. **더보기 > 앱 설정**(`src/screens/more/MoreScreens.jsx` AppSettingsScreen)에 **[앱 새로고침]** 단추를 항상 보이게 넣는다. 설명 글: "화면이 이상하거나 옛날 화면이 보이면 눌러 주세요". 누르면 3번과 같은 "캐시 비우고 새로고침". 지금 보고 있는 판 번호(빌드 시각을 "2026-11-03 16:40 판"처럼)도 작게 표시.
5. **캐시 규칙 파일**: `public/_headers`를 만든다(Cloudflare Pages 규칙).
   ```
   /index.html
     Cache-Control: no-cache
   /
     Cache-Control: no-cache
   /sw.js
     Cache-Control: no-cache
   /version.json
     Cache-Control: no-store
   /assets/*
     Cache-Control: public, max-age=31536000, immutable
   ```
6. `public/sw.js`는 건드리지 않는다(푸시 알림이 걸려 있다).

## 끝낼 때
공통 규칙대로. 검토 md 이름은 `학생앱142차수-검토.md`. 검토 md에 "원장이 새 판을 올린 뒤 학생 폰에서 몇 분 안에 띠가 뜨는지"를 한 줄로 적는다.
