# 10단계 — 학생앱 "녹음 제출" 화면 (학생앱 145차수, 가지 `cloud-step10-1104`)

먼저 `docs/cloud-1103/0-공통규칙.md`를 읽는다. main 최신(144차수)에서 가지를 딴다.

## 무엇을 만드나
학생이 폰에서 **소리를 녹음해 학원에 제출**하는 화면. 선생님은 원장앱 PDF 수업실에서 듣는다(원장앱 299차수·워커에서 따로 만든다). "무엇을 읽을지"는 아직 안 정했으니 **기능만**: 학생이 "읽은 내용"을 한 줄 적고(선택) 녹음해 보내면 된다.

## 워커 길(API) — 이미 정해진 모양(원장앱 쪽 9단계와 같음)
워커 주소는 `src/core/config.jsx`의 `WORKER_ORIGIN`. 학생 토큰은 `src/core/bundle.jsx`의 `getSelfAccessToken()`. 부르는 방식은 `src/domain/vocabTest.jsx`의 `/vocab-test-result` 저장(fetchWithTimeout + JSON)과 같게.
1. `POST ${WORKER_ORIGIN}/student/recording` — body `{ studentId, t, label, dur, mime, dataBase64 }`
   - `label` 읽은 내용(80자까지, 비어 있어도 됨), `dur` 초(1~90), `mime` = 녹음한 형식(`audio/webm` | `audio/mp4` | `audio/ogg`), `dataBase64` = 파일(2MB까지).
   - 답 `{ success:true, id, key, at }`. 413이면 "녹음이 너무 길어요", 401/403이면 "앱을 새로고침한 뒤 다시 해 주세요".
2. `GET ${WORKER_ORIGIN}/student/recordings?studentId=&t=` — 내 녹음 목록(최근 30일, 최신 먼저). 답 `{ success:true, items:[{ id, date, label, key, dur, mime, at, heard, memo }] }`.
3. 다시 듣기: `GET ${WORKER_ORIGIN}/files/<key>?sid=<studentId>&t=<토큰>` 를 `<audio src>`에 바로 넣어도 된다(워커가 본인 확인 뒤 내준다).
워커가 아직 안 올라갔을 수 있으니, 404/연결 실패는 "지금은 제출할 수 없어요. 잠시 뒤 다시 해 주세요"로 조용히 처리한다.

## 화면
1. **더보기 탭 메뉴에 한 줄 추가** — `src/state/computeMoreView.jsx`의 "학습" 묶음(모의고사 줄 **위**)에 `{ key: "record", icon: "🎤", title: "녹음 제출", sub: "읽고 녹음해서 보내기" }`. `src/App.jsx`에 `<MoreSubFrame title="녹음 제출">`로 새 화면을 단다(다른 더보기 화면과 같은 방식, 탭 이동은 `goTab`/`makeTabNav` 규칙대로).
2. **새 화면 `src/screens/more/RecordScreen.jsx`** (한 파일, 인라인 style, TAP 크기·토스 분위기 유지):
   - 위: "읽은 내용" 입력칸(한 줄, 80자, 안 적어도 됨, 안내 글 "예: 단어 10개 / 본문 3번 문장").
   - 가운데 큰 둥근 단추 **[● 녹음 시작]** → 누르면 마이크 권한 요청 → 녹음 중엔 빨간 점 + `0:07 / 1:30` 시간 + **[■ 정지]**. **90초가 되면 자동 정지.**
   - 정지 뒤: 파형 대신 간단한 재생 막대 + **[▶ 들어보기]** · **[↺ 다시 녹음]** · **[제출]**(남색 primary).
   - [제출] 누르면 "보내는 중…" → 성공하면 "제출했어요 ✓" 2초 띄우고 목록 맨 위에 추가, 입력칸·녹음 비움.
   - 아래: "내가 보낸 녹음" 목록(최근 30일, 날짜별 묶음). 항목마다 날짜·시간, 길이 `0:23`, 읽은 내용, 선생님이 들었으면 **"선생님 확인 ✓"** 초록 작은 글씨, 메모가 있으면 그 아래 한 줄. [▶] 누르면 그 자리에서 재생(한 번에 하나만).
   - 목록은 화면에 들어올 때 한 번 받고, 제출 뒤 다시 받는다. 당겨서 새로고침은 안 만들어도 된다.
3. **녹음 기술**
   - `navigator.mediaDevices.getUserMedia({ audio: true })` + `MediaRecorder`. 형식은 `MediaRecorder.isTypeSupported`로 `audio/webm;codecs=opus` → `audio/webm` → `audio/mp4` → `audio/ogg` 순서로 되는 첫 것. 아이폰 사파리는 `audio/mp4`가 된다. 아무것도 안 되면 "이 폰에서는 녹음이 안 돼요" 안내.
   - `audioBitsPerSecond: 32000`(가능할 때). 90초면 약 400KB.
   - 권한 거부·마이크 없음 → "마이크 사용을 허용해 주세요" 안내 + [다시 시도].
   - 녹음 중에 탭을 바꾸거나 화면을 나가면 녹음을 멈추고 버린다(제출 안 됨). 마이크 스트림은 꼭 끈다(`track.stop()`).
   - base64 변환은 FileReader(`readAsDataURL`)로, `data:…;base64,` 앞부분은 떼고 보낸다.
   - 142차수의 "시험·영상 중이면 업데이트 안 함" 같은 규칙이 있으면 녹음 중에도 같은 보호를 넣는다(녹음 중 새 판 적용 금지).
4. **홈 화면은 건드리지 않는다**(무엇을 녹음시킬지 정한 뒤에 홈 줄을 붙인다).
5. `src/core/config.jsx`의 `STUDENT_APP_BUILD`를 `"학생앱 145차수 · 2026-11-04 · 녹음 제출 화면"`으로.

## 정한 것(원장 확정)
- 녹음 최대 90초, 파일 2MB. 30일 뒤 자동 삭제(워커가 함 — 화면에는 "30일 동안 보관돼요" 작은 안내 한 줄).
- "읽은 내용"은 선택 입력. 선생님 TTS 비교에 쓰인다.

## 확인할 것(검토 md에 적는다)
- 빌드 통과. 더보기 → 녹음 제출 화면이 열리는지. 녹음 시작/정지/들어보기/다시 녹음이 되는지(크롬 데스크톱에서 마이크로 확인). 90초 자동 정지.
- 워커가 없을 때(지금) 제출하면 조용한 안내가 뜨고 앱이 멈추지 않는지.
- 아이폰 사파리에서 `audio/mp4`가 골라지는 코드가 있는지(실기기 확인은 원장).
