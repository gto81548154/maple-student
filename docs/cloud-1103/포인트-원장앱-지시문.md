# 원장앱(academy-mgmt) 지시문 — 마플 포인트 화면

> 이 글을 원장앱 작업 창에 그대로 붙여 넣으면 됩니다.
> 워커(마플싱커)는 "워커 11-21판 마플 포인트"가 이미 올라가 있다고 보고 만듭니다. 워커 코드는 고치지 않습니다.

## 무엇을 만드나

학생이 포인트를 모아 상점에서 주문하면 원장이 사서 보내 주는 "마플 포인트" 제도를 12월 1일에 시작합니다.
포인트 계산·저장은 전부 워커가 합니다. 원장앱은 **워커 문을 불러서 보여 주고 단추를 누르는 화면**만 만듭니다.
원장앱이 kv_store의 포인트 키(`point_config_v1`, `pt1:…`, `point_orders_v1`, `point_state_v1`)를 직접 읽거나 쓰면 안 됩니다. 반드시 아래 워커 문만 씁니다.

규칙(1포인트 = 1원):

| 항목 | 포인트 | 누가 넣나 |
| --- | --- | --- |
| 제시간 등원(정규 수업 날, 지각 아님, 보충 날 제외) | 100 | 워커 자동 |
| 숙제 다 함 / 일부만 함 | 100 / 50 | 워커 자동(숙제 칸 체크 기준) |
| 단어 TEST 한 번에 통과(하루 한 번) | 100 | 워커 자동(단어 TEST 칸 체크 기준) |
| 한 달 개근(지각·결석 0) | 1,000 | 워커 자동(다음 달 2일) |
| 단어 리그 1·2·3등 | 3,000 · 2,000 · 1,000 | 워커 자동(리그 끝난 다음 날) |
| 성적 장학금 | 10,000 | 원장이 "지급 완료" 누를 때 |
| 성적 향상 장학금(중 10점↑ / 고 1등급↑) | 5,000 | 원장이 "지급 완료" 누를 때 |
| 친구 소개 — 상담 / 등록 | 3,000 / 30,000(둘 다) | 원장이 누를 때 |
| 원장 직접 지급 | 자유 | 원장 |

## 만들 화면

장학금·친구 소개 신청을 보는 지금 화면 옆(같은 메뉴 묶음)에 **"포인트"** 메뉴를 만들고, 안에 탭 4개를 둡니다.
인증은 장학금 신청 화면(`/admin/reward-claims`)을 부를 때와 똑같은 관리자 열쇠·같은 호출 함수를 씁니다.

### 탭 1. 주문 (처음 열리는 탭)

- `GET /admin/point-orders?status=pending` 로 기다리는 주문을 최신순으로 보여 줍니다. 위에 알약으로 `기다리는 중 · 보냄 · 거절 · 취소 · 전체`를 바꿉니다(`status=pending|sent|rejected|canceled|all`).
- 한 줄: 학생 이름(학교·학년) · 상품 이름 · 금액 · 주문 시각 · 상태.
- 기다리는 주문에는 단추 2개:
  - **보냄** → `POST /admin/point-order/status` `{ id, status:"sent", reason:"" }` (reason에 한 줄 메모를 넣을 수 있음. 예: "카톡으로 보냈어요")
  - **거절** → 이유를 꼭 받은 뒤 `{ id, status:"rejected", reason }` (워커가 포인트를 학생에게 돌려줍니다)
- 이미 처리된 주문은 409(`not_pending`)가 옵니다 → "이미 처리된 주문이에요" 띄우고 목록 새로 고침.
- 메뉴 이름 옆에 기다리는 주문 수 배지: `GET /admin/point-orders/count` → `{ pending }`. 장학금 신청 배지와 같은 방식(같은 주기)으로 불러옵니다.

### 탭 2. 학생 포인트

- `GET /admin/points` → `{ students:[{ studentId, name, school, grade, paused, balance, earned, used, count }], total }`. 잔액 많은 순. 이름 검색 칸.
- 학생을 누르면 `GET /admin/points?studentId=` → `{ balance, items:[{ id, date, kind, label, amount, at, by }] }` 내역(최신순).
  - 금액이 +면 초록, -면 빨강. `by`가 `admin`이면 "직접", `worker`면 "자동", `student`면 "주문"이라고 작게.
  - 각 줄에 **지우기** 단추 → 확인창 뒤 `POST /admin/point-entry/delete` `{ studentId, entryId }`. 주문·환불 줄(`kind`가 `order`·`refund`)에는 단추를 안 보입니다.
- **포인트 주기 / 빼기** 단추 → `POST /admin/point-grant` `{ studentId, amount, label }`. amount는 +면 주기, -면 빼기. label(이유)은 꼭 받습니다.
  - 설정의 "자주 쓰는 지급"(`config.grants`)을 칩으로 보여 주고, 누르면 금액·이유가 채워지게.
  - 여러 학생을 체크해서 한 번에 주기: `{ studentIds:[…], amount, label }`.
  - 지난(12월 전) 장학금·친구 소개를 포인트로 넣어 줄 때도 이 단추를 씁니다.
- **다시 계산** 단추(작게) → `POST /admin/points/recalc` `{ dates:["2026-12-03"] }`. 선생님이 지난 날 체크를 고친 뒤 포인트를 다시 맞출 때. 날짜를 고르게 하고(여러 날 가능, 31일까지), 결과의 `changed` 수를 보여 줍니다.

### 탭 3. 상점 상품

- `GET /admin/point-config` → `{ config:{ enabled, startDate, rules, products, grants }, ruleLabels, on }`.
- `config.products` = `[{ id, name, emoji, image, prices:[10000,20000,30000], on }]` 를 목록으로 보여 주고 넣기·고치기·빼기·순서 바꾸기·켜고 끄기(on).
  - 새 상품의 id는 원장앱이 만듭니다(영문·숫자, 예: `p_` + 시각). 이미 있는 id는 바꾸지 않습니다.
  - 가격은 여러 개(최대 8개), 숫자만. 이미지(image)는 주소 한 줄(비워도 됨), emoji는 이모지 한 글자.
- 저장: `POST /admin/point-config` `{ config:{ products:[…전체 목록…] } }`. **준 칸만 바뀝니다**(products를 주면 목록 전체가 그것으로 바뀜).

### 탭 4. 설정

- **포인트 켜기** 스위치(`enabled`)와 **시작일**(`startDate`, 처음 값 2026-12-01). 꺼져 있으면 워커가 아무것도 계산하지 않고 학생앱에 메뉴가 안 보입니다. 화면에 "지금 켜짐/꺼짐(시작일 전)"을 `on` 값으로 보여 줍니다.
- **항목별 포인트**(`rules`): `ruleLabels`의 이름으로 숫자 칸을 보여 줍니다. 0으로 두면 그 항목은 안 줍니다. `perfectMinDays`는 "개근으로 치는 최소 등원 횟수"라고 따로 보여 줍니다.
- **자주 쓰는 지급**(`grants`) = `[{ id, label, amount }]` 넣기·빼기. (예: "칭찬 500", "이벤트 1000")
- 저장: `POST /admin/point-config` `{ config:{ enabled, startDate, rules:{…바꾼 것만…}, grants:[…] } }`.

## 장학금·친구 소개 화면 고치기 (지금 있는 화면)

`GET /admin/reward-claims` 응답 한 줄에 칸이 늘었습니다: `improveType, prev, now, points, consultPoints, usesPoints`.

1. **성적 향상 장학금** — `kind`가 `"improve"`인 신청이 새로 옵니다.
   - `level:"middle"` + `improveType:"score10"` → "지난 시험 `prev`점 → 이번 `now`점 (+N점)"
   - `level:"high"` + `improveType:"grade1"` → "지난 시험 `prev`등급 → 이번 `now`등급"
   - 성적표·정오표 사진(`photoKey`)은 성적 장학금과 같은 방식으로 보여 줍니다.
   - **원장이 다시 확인하게**: "지급 완료"를 누르면 바로 보내지 말고 확인창을 띄웁니다 — "학원 기록과 대조했나요? 지난 시험 OO → 이번 OO. 포인트 5,000P가 들어갑니다." [확인했어요 · 지급] / [취소].
   - 지급·거절은 지금과 같은 `POST /admin/reward-claim/status` `{ id, status, reason }`.
2. **친구 소개 상담 단추** — `kind:"referral"`이고 `usesPoints`가 true이고 `consultPoints`가 0인 신청에 **"상담 왔어요 (+3,000P)"** 단추를 둡니다.
   → `POST /admin/reward-claim/status` `{ id, status:"checking", reason:"", consulted:true }`. 응답 item의 `consultPoints`가 3000이 되면 단추를 "상담 포인트 지급됨"으로 바꿉니다.
   (상담 단추를 안 누르고 바로 "지급 완료"를 눌러도 워커가 상담 3,000P + 등록 30,000P를 같이 넣습니다.)
3. **글 바꾸기** — `usesPoints`가 true인 신청은 "기프티콘" 대신 "포인트"라고 씁니다(예: "지급 완료 → 10,000P 들어감"). `points`가 숫자면 "포인트 N P 지급됨"을 보여 줍니다. `usesPoints`가 false(12월 전 신청)는 지금처럼 기프티콘 글 그대로.
4. 성적 장학금과 성적 향상 장학금이 같은 시험이면 워커가 큰 쪽 하나만 넣습니다(차액만 넣거나 0). 원장앱은 응답의 `points`를 그대로 보여 주기만 합니다.

## 꼭 확인하고 알려 줄 것 (워커가 이 가정으로 계산합니다)

원장앱 코드를 보고, 아래가 **실제와 다르면 고치지 말고 검토 글 맨 위에 적어 주세요**(워커를 맞춰야 합니다).

1. 숙제 체크는 `chk3[날짜][학생id]["step1_0"]`, `["step1_1"]`… 에 저장된다. 통과 = `true` 또는 `"done"`, 미완료 = `"fail:이유"`, 일부러 끔 = `"__todo_clear__"`.
2. 단어 TEST 체크는 같은 곳에 `"step2_0"`, `"step2_1"`… 로 저장되고, **재시험이 되면 그 칸이 `"fail:…"`로 저장된다**(재시험을 통과하면 다시 `true`로 바뀐다). 워커는 매시간 이 칸을 보고 "한 번이라도 fail이었던 날"은 한 번에 통과로 치지 않는다.
   - 만약 재시험을 다른 곳(AI 채점 기록 등)에 적는다면 그 키 이름과 모양을 알려 주세요.
3. 지각·결석은 `att3[날짜][학생id] = { type:"late"|"absent"|"present", time }` 에 저장되고, 등원 QR은 `att_log3[날짜][학생id].inAt` 에 저장된다. **지각은 선생님이 직접 표시해야만 `late`가 된다**(QR 시각으로 자동 지각 처리가 되는지 여부도 알려 주세요).
4. 보충은 `mkp3` 배열의 `{ studentId, date, isHidden, isOverride }` — `isOverride !== true`이고 `isHidden`이 아니면 보충 날.

## 끝낼 때

- 지시한 것만 고칩니다. 화면 글은 한국어, 기존 화면(장학금 신청 화면)의 모양·색·단추 크기를 그대로 따릅니다.
- 워커가 아직 옛 판이면 `/admin/point-config`가 404입니다 → "워커를 먼저 올려 주세요" 한 줄만 보여 주고 다른 화면은 멀쩡해야 합니다.
- 빌드 성공 확인 → 평소 규칙대로 커밋·올리기 → 검토 글(전에는 / 지금은 / 확인법).
